Privacidad de Screener Drive Sync

Screener Drive Sync conecta la cuenta de Google Drive autorizada por el propietario con las corridas privadas de Dashboard Nodriza. Esta información describe esa integración y las copias de archivos que utiliza.

Datos a los que accede

La integración lee y descarga archivos de insumos y caches, y crea o actualiza resultados en Drive. También consulta metadata para localizar archivos y comprobar las transferencias: nombres, rutas, tamaños, fechas de modificación y hashes cuando están disponibles.

Los archivos del proyecto pueden contener información financiera, parámetros de trabajo, carteras y resultados de análisis. Su contenido depende de los insumos que incorpora el propietario. No se presume que todos los archivos sean datos públicos.

El permiso OAuth de Drive es amplio: permite ver y administrar los archivos accesibles para la cuenta autorizada. Los procesos habituales usan una raíz de proyecto y filtros para Input Data y Output. Esos controles delimitan la operación; no convierten el permiso OAuth en acceso exclusivo a esas carpetas.

Finalidad del uso

Los archivos y su metadata se utilizan para preparar y ejecutar las corridas de Dashboard Nodriza, recuperar históricos y caches, verificar consistencia y conservar los resultados autorizados. Los datos obtenidos mediante esta integración no se usan para publicidad ni se venden.

Dónde se procesan y quién puede acceder

Las transferencias se realizan con rclone desde la estación de trabajo local o desde runners de GitHub Actions asociados al repositorio privado. Google procesa las solicitudes de Drive y almacena los archivos que permanecen allí. GitHub procesa los jobs y puede conservar logs, caches y artifacts según la configuración del repositorio y del servicio.

El acceso operativo corresponde al propietario y a las personas o procesos que este autorice mediante los permisos del equipo, de Drive y del repositorio. La privacidad del repositorio no sustituye la revisión de esos permisos. Google y GitHub también intervienen como proveedores de infraestructura, conforme a las condiciones y controles de sus servicios.

La transferencia a GitHub Actions implica procesamiento en infraestructura de nube; los datos no permanecen exclusivamente en el equipo local. Compartir un archivo de Drive, un output o un artifact mediante sus propios permisos también puede ampliar quién lo recibe.

Credenciales de autorización

Los tokens y la configuración OAuth de rclone se conservan en archivos privados para la ejecución local y en un Secret de GitHub para las corridas remotas. El workflow crea el archivo de configuración del runner con permisos de acceso limitados al usuario del proceso. El propietario debe proteger también los respaldos privados y los permisos de acceso a esos entornos.

La contraseña de la cuenta de Google se introduce ante Google durante la autorización, no como un insumo de Dashboard Nodriza. Estas páginas no solicitan credenciales, no contienen formularios y no incorporan scripts de seguimiento ni recursos de terceros.

Visitas a estas páginas

El código de estas páginas no incorpora analítica propia. Si se alojan en GitHub Pages, GitHub registra y conserva la dirección IP de las visitas por motivos de seguridad, según su documentación. La ausencia de scripts de seguimiento propios no impide ese registro del proveedor de alojamiento.

Conservación y eliminación

No se aplica un plazo único de conservación a todos los archivos de la integración. La conservación de insumos, históricos, outputs, caches y respaldos depende de las decisiones del propietario y de la configuración de cada ubicación. GitHub y Google pueden aplicar sus propias reglas de almacenamiento y conservación.

Para eliminar datos, el propietario debe gestionar las copias que correspondan en Drive, el equipo local y GitHub, incluidos respaldos, caches y artifacts. Eliminar una copia no elimina automáticamente las demás.

Revocar el acceso

El propietario puede revisar y retirar el acceso de Screener Drive Sync en las conexiones con aplicaciones de su cuenta de Google. Al retirarlo, la integración deja de contar con esa autorización para acceder a Drive y las próximas transferencias pueden fallar hasta que se autorice de nuevo.

Revocar la autorización no borra automáticamente los archivos de Drive, los resultados generados ni las copias ya descargadas o conservadas en otros entornos. El propietario puede detener las corridas y retirar además la configuración local y el Secret de GitHub si deja de utilizar la integración.
